## Milestone M6 — Async Drift Healer & Non-Blocking Tray Tier-2 Fallback (`v1.5.0`)

*Bottleneck / escape context:* Live `2026-11-26` YouTube drift healing exposed three coupled blocking/timeout failures: synchronous `runDriftHealer(r.Context(), ...)` exceeds `DesktopClient`'s `30s` HTTP timeout and cancels Vertex AI healing mid-flight (`escape_cause: fake_drift` — instant unit `stubHealer` never outlived `r.Context()`), pre-approval waits miss `startTaskHeartbeat` so `90s` Tier-2 fallback leases expire (`MaxAttempts: 1` → `dead_letter`, `escape_cause: missing_unit_case`), and inline Win32 `MessageBoxW` freezes `workerLoop` timers and tray actions (`escape_cause: env_parity` — Windows-only `trayApp` loop lacked cross-platform concurrency tests).

- [ ] **M6.1 (P1, 0.5d) — Asynchronous server drift healing on `/v1/tasks/{id}/fail`, `/fallback-result`, and `/errors`:** *(Implemented locally — pending `v1.5.0` release)* Moved `s.runDriftHealer(...)` off request-scoped `r.Context()` handlers ([`internal/server/http_proposals.go`](../internal/server/http_proposals.go), [`internal/server/http.go`](../internal/server/http.go), [`cmd/server/main.go`](../cmd/server/main.go)) onto a bounded async background worker queue with detached lifecycle context, `(task.ID, diagID)` deduplication, immediate `claimed -> failed_diagnostic` lease release on `/fallback-result`, bounded `HealerTimeout` (`120s`), and graceful `Shutdown` drain (`regression_test`: `TestM61AsyncDriftHealerSurvivesCancelledRequestDeduplicatesAndDrains`).
- [ ] **M6.2 (P1, 0.25d) — Start task lease heartbeat before Tier-2 `FallbackApprover` prompt:** *(Implemented locally — pending `v1.5.0` release)* Started `startTaskHeartbeatInterval` ahead of `awaitFallbackApproval` in [`cmd/deskdrop/sync.go`](../cmd/deskdrop/sync.go) with a bounded prompt auto-decline budget (`3m` default) independent of `DefaultLease` `90s` (`regression_test`: `TestM62FallbackTaskHeartbeatsBeforeSlowApprovalAndAutoDeclinesOnTimeout`).
- [ ] **M6.3 (P1, 0.5d) — Decouple `--fallback-gate=tray` confirmation from `trayApp.workerLoop`:** *(Implemented locally — pending `v1.5.0` release)* Extracted cross-platform non-blocking [`cmd/deskdrop/tray_worker.go`](../cmd/deskdrop/tray_worker.go) wired into [`cmd/deskdrop/tray_windows.go`](../cmd/deskdrop/tray_windows.go) (`MessageBoxTimeoutW` auto-dismiss, async sync/fallback execution, driver-only `execMu`, zero `90s` `runSyncCycle` timeout; `regression_test`: `TestM63TrayCoordinatorNonBlockingFallbackKeepsTickersAndActionsResponsive`).
- [ ] **M6.4 (P1, 0.25d) — Release `v1.5.0` to GKE + Windows tray & verify live Tier-2 drift healing:** Run `scripts/gate.sh`, `make build`, Cloud Build rollout (`ship deskdrop minor`), and Windows tray self-update to `v1.5.0`, then verify fast `/fail` return and non-blocking Tier-2 fallback handling.

## Milestone M7 — Declarative Scroll Pagination & Drop Diffing (`v1.5.0`)

*Bottleneck / rollout order:* Virtualized infinite-scroll feeds recycle DOM nodes instead of rendering a "Next page" button, and `ReloadableCatalog` decodes `RECIPES_URI` with `contract.ParseJSONStrict` (`CRITICAL.md` §2) — deploy `deskdrop-server` `v1.5.0` *before* uploading any recipe that uses new `PaginationRule` keys.

- [ ] **M7.1 (P2, 0.5d) — Declarative `mode: "scroll"` pagination across `contract`, `cdp`, `verify`, and `specs`:** *(Implemented locally — pending `v1.5.0` release)* Extended `PaginationRule` ([`internal/contract/pagination.go`](../internal/contract/pagination.go)) with `mode: "click" | "scroll"` and bounded `scroll_delta_y` (`1..5000`, default `900`), updated [`internal/driver/cdp/paginate.go`](../internal/driver/cdp/paginate.go) (`window.scrollBy`), [`internal/verify/paginate.go`](../internal/verify/paginate.go), [`specs/deskdrop.yaml`](../specs/deskdrop.yaml), and [`specs/deskdrop.behavior.yaml`](../specs/deskdrop.behavior.yaml) (`TestM71ScrollPaginationContractValidation`, `TestM71ScrollPaginationLoopsUntilLimitOrNoNewAndGuardsDomain`, `TestM71VerifyRecipeOnHTMLPagesScrollModeVirtualizedFeed`).
- [ ] **M7.2 (P2, 0.5d) — Drop item diffing (`added` / `removed`) with top-N window-shift guard:** *(Implemented locally — pending `v1.5.0` release)* Added [`internal/contract/diff.go`](../internal/contract/diff.go) (`DiffStepItems`, `ComputeDropDiff`), `Store.GetPriorDrop` ([`internal/server/store_memory.go`](../internal/server/store_memory.go), [`internal/server/store_file.go`](../internal/server/store_file.go)), and `GET /v1/drops/{id}/diff` + `/desktop/v1/drops/{id}/diff` ([`internal/server/http.go`](../internal/server/http.go), [`specs/deskdrop.yaml`](../specs/deskdrop.yaml)) (`TestM72DiffStepItemsAndComputeDropDiffWindowShiftGuard`, `TestM72HandleDiffDropEndpointAndQueryOverrides`).
- [ ] **M7.3 (P2, 0.25d) — Ship `v1.5.0` server before `RECIPES_URI` scroll-recipe rollout:** Deploy `deskdrop-server` `v1.5.0` first via [`cloudbuild.yaml`](../cloudbuild.yaml), then publish any infinite-scroll recipe to `RECIPES_URI` and verify live top-10/25 extraction and `/v1/drops/{id}/diff` end-to-end.
