## Milestone M6 — Async Drift Healer & Non-Blocking Tray Tier-2 Fallback (`v1.4.4`)

*Bottleneck / escape context:* Live `2026-11-26` YouTube drift healing exposed three coupled blocking/timeout failures: synchronous `runDriftHealer(r.Context(), ...)` exceeds `DesktopClient`'s `30s` HTTP timeout and cancels Vertex AI healing mid-flight, pre-approval waits miss `startTaskHeartbeat` so `90s` Tier-2 fallback leases expire (`MaxAttempts: 1` → `dead_letter`), and inline Win32 `MessageBoxW` freezes `workerLoop` timers and tray actions. Follow the [`AGENTS.md`](../AGENTS.md) escape-analysis rule on each fix (`escape_cause`, targeted unit test, and 1-line mutant verification).

- [ ] **M6.1 (P1, 0.5d) — Asynchronous server drift healing on `/v1/tasks/{id}/fail`, `/fallback-result`, and `/errors`:** Move `s.runDriftHealer(...)` out of request-scoped `r.Context()` handlers ([`internal/server/http_proposals.go`](../internal/server/http_proposals.go) lines `145-153`, `260-270`, `343-376`) onto a bounded async background worker with a detached lifecycle context, deduplication by `(task.ID, diagID)`, bounded healer deadline, and clean shutdown drain so `DesktopClient`'s `30s` HTTP timeout ([`internal/bus/service.go`](../internal/bus/service.go) line `111`) cannot cancel `HealDrift` mid-loop. *Done when:* `/v1/tasks/{id}/fail` and `/fallback-result` return immediately (`<100ms`), slow healer completion persists `RecipePatchProposal`/Tier-2 task/fallback closure after `r.Context()` cancels, and `internal/server/` regression + mutant tests pass under `-race`.
- [ ] **M6.2 (P1, 0.25d) — Start task lease heartbeat before Tier-2 `FallbackApprover` prompt:** Move `startTaskHeartbeat` ahead of `approver(plan)` in `execFallbackTask` ([`cmd/deskdrop/sync.go`](../cmd/deskdrop/sync.go) lines `288-311`, `391-407`) using a heartbeat context spanning approval wait + step execution and a bounded prompt budget independent of `DefaultLease` `90s` ([`internal/server/http.go`](../internal/server/http.go) line `58`, [`internal/server/store_memory.go`](../internal/server/store_memory.go) lines `547-564`) so slow human prompts do not expire into `dead_letter` or `409 TASK_NOT_CLAIMED`. *Done when:* a blocking fake `FallbackApprover` emits `HeartbeatTask` pings before returning and cancels cleanly on decline/timeout under `-race`.
- [ ] **M6.3 (P1, 0.5d) — Decouple `--fallback-gate=tray` confirmation from `trayApp.workerLoop`:** Run Tier-2 fallback prompting/execution asynchronously off `workerLoop` ([`cmd/deskdrop/tray_windows.go`](../cmd/deskdrop/tray_windows.go) lines `188-200`, `465-507`, `633-684`) with bounded auto-decline timeout instead of blocking `workerLoop` inside `procMessageBoxW.Call(...)` and a fixed `90s` `runSyncCycle` timeout. *Done when:* `syncTicker`, `probeTicker` (`sendBackgroundHeartbeat`), and tray `actionCh` commands remain responsive while a Tier-2 confirmation prompt is open, verified with cross-platform concurrency + timeout tests.
- [ ] **M6.4 (P1, 0.25d) — Release `v1.4.4` to GKE + `win-pc` tray & verify live Tier-2 drift healing:** Run `scripts/gate.sh`, `make build`, Cloud Build rollout, and `win-pc` tray self-update to `v1.4.4`, then trigger a controlled `SELECTOR_DRIFT` drill confirming fast `/fail` return, >`90s` Tier-2 prompt survival without `dead_letter` or frozen heartbeats, and clean approval/decline handling.
